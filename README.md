# 绿茵阵容实验室

双击 `启动网页.cmd`，或直接在浏览器打开 `dist/index.html`。网页无需安装依赖或联网；GitHub Pages 使用同一份 `dist` 静态文件。

首次打开时，网站会载入 `dist/default-data.js` 中的默认球员、组合和比赛位置。此后玩家的添加、修改、删除和候选选择保存在各自浏览器的本地存储中，不会修改网站上的默认资料，也不会同步给其他玩家。换浏览器或清除浏览器数据前，请点击右上角“导出资料”保存 JSON。“导入资料”可选择合并球员与组合（保留当前比赛位置），或替换全部资料和位置设置。

仓库的 `.github/workflows/pages.yml` 在推送到 `main` 时将 `dist` 发布到 GitHub Pages。仓库设置中的 Pages 来源应选择 GitHub Actions。

“关联分析”选项卡使用整个球员资料库，每个球员只统计一次，同一人的不同评分版本不会重复计数。球队网络将球员的曾效力球队两两连线，线的粗细代表共同球员人数；可筛选最少共同人数，点击球队或连线查看具体球员。位置热图的非对角格表示“可踢行位置的球员中，也可踢列位置的比例”，两个方向的百分比可能不同；对角格表示“可踢该位置的人中，仅填写该位置的比例”。它反映资料中填写的可踢位置，不是实际上场次数。国家与球队热图展示各国球员曾效力某队的人数，或该人数占资料库中该国球员的比例。点击热图格子可查看球员并打开资料编辑。这些分析依赖手动录入资料，样本少时比例可能波动较大。

球队共享球员矩阵沿用位置热图的方向读法：交叉格显示两队共享球员人数和其占行球队球员的比例，对角格显示仅填写该队作为曾效力球队的球员。可选择显示最多 12、20 或 30 支球队，点击格子查看共同球员及其资料。由于分母按行计算，同一对球队的两个方向百分比可能不同。

关联分析的“聚类”可切换球员、球队和位置。球员聚类按可踢位置、曾效力球队和国籍计算加权相似度，可选择综合、位置、球队或国籍侧重点。球队聚类按两队曾效力球员的交集占并集比例分组；位置聚类按可踢两个位置的球员交集占并集比例分组。可设置最多分组数、点击组卡查看成员，并查看关联球员。没有与其他对象共享资料的成员会单独列出。聚类是探索性分组，结果受手动录入资料、侧重点和组数影响，不代表历史同期效力或实际出场位置。

切换到“球队聚类”时，下方还会显示球队相似度矩阵。矩阵使用平均连接层次聚类排列行列，让共享球员比例较高的球队尽量靠近；每格的百分比为两队共同球员数除以两队球员并集人数，对角线为 100%。可选择显示资料库球员最多的 12、20 或 30 支球队，点击格子查看共同球员。矩阵的排列顺序与上方的代表球队分组分别计算。

普通模式需要至少 19 名候选球员。比赛模式可分别指定 11 个首发位置，允许重复，也可先套用阵型模板再修改；7 个替补位置和预备队位置不限定场上位置。比赛模式中可在每个位置搜索球员，没找到时直接创建，保存后会自动加入该位置。“随机填满空位”会从资料库为每个位置随机补充最多 5 名候选，保留已有的有效候选，清除当前首发位置不允许的候选，并尽量确保各位置能选出不同球员。资料库中合适的球员不足时会提示未填满的位置。每个位置至少需要 1 名候选，每组最多 5 人，计算时每组至多选 1 人，同一球员不会重复入选。球员进入首发时必须能踢该位置。

比赛模式的“一键清空候选”会清空首发、替补和预备队所有位置的候选球员及当前计算结果；已设置的位置和球员资料库保留。

比赛模式已加入位置候选中的球员姓名和评分可以点击，直接打开该评分版本的资料窗口查看、修改；右侧的 × 只从该位置移除候选。球员资料库支持直接输入中文姓名或国籍进行筛选。

比赛模式计算完成后，位置候选列表会高亮最终首发球员，以及参与至少一项已触发化学反应加成的替补球员。所有进入最终 18 人名单的选中球员都会显示最终首发位置或替补序号；未贡献加成的替补只显示去向，不高亮。若预备队位置选中的球员没有进入最终 18 人名单，则不会高亮。调整位置、候选或搜索设置后，旧结果与高亮会一同清除。

默认优化目标为“最终分数”：首发总评分 + 化学反应 × (1 + 评分档位加成)。球队、国家和三人组合的加成先合计，化学反应最多按 100 计入；超过 100 的原始合计仍会在结果明细中显示。例如首发总评分 1050、化学反应达到 100 时，档位加成 320%，最终分数为 1050 + 100 × 4.2 = 1470。也可切换为“化学优先”或“评分优先”；这两种模式分别先比较封顶后的化学反应或首发总评分，再以另一项打破平局。计算采用限时搜索，因此展示的是当前找到的最佳方案，不保证数学意义上的全局最优。

计算结果中的球队、国家和三人组合加成可以点开，分别查看计入该项的首发与替补球员；球员姓名可点击打开资料。

普通模式和比赛模式的“算法”按钮可打开搜索设置。普通模式保留原有模拟退火；比赛模式可选择模拟退火或“目标引导分层搜索”。模拟退火可调整搜索时长（默认 5 秒）、探索强度（默认 1 倍，数值越大越容易暂时接受较差方案）、重新生成起点的间隔（默认 7000 次，设为 0 可关闭）。

目标引导分层搜索先根据每个比赛位置的候选，找出理论上能达到至少 6 人加成的球队、国家目标，再围绕这些目标生成和调整候选名单。每次确定一份 18 人名单后，它会精确比较这 18 人所有可行的首发 11 人组合，并将其余 7 人放入替补。若有预备队位置，算法也能从已选中的预备队球员中挑选进入 18 人名单。球队和国家只引导搜索，不作为硬性入选条件。固定 18 人的首发与替补分配可求精确最优，但在规定时间内搜索不同的 18 人名单，整体结果仍不保证全局最优。此算法可设置搜索时长和最多考虑的球队／国家目标数。所有设置随浏览器数据保存，也包含在导出的 JSON 中。

首发总评分低于 990 时，评分档位加成为 0%。从 990 分起，评分门槛按 5、6 分交替增加；化学加成的每档增量按 +15、+15、+20、+20、+25、+25……递增。已核实的档位包括 990→30%、995→45%、1001→60%、1006→80%、1012→100%、1017→125%、1023→150%、1028→180%、1034→210%、1039→245%、1045→280%、1050→320%、1056→360%、1061→405%。更高分数按同一档位规律继续计算。

添加或编辑球员时，输入姓名即可查看已有的相关三人组合。可在同一窗口连续添加新组合，保存球员时一起保存；其他两名成员尚未入库也可以填写。球员资料库会显示每名球员所属的组合。

国籍输入框会提示资料库里已有的国籍，也可以直接输入新国籍。球队输入框同样支持从已有球队中选择或输入新球队；按回车或点击“添加”可逐个加入，已加入的球队可以点 × 移除。直接输入后点击“保存球员”也会保存该球队。

同一球员可添加多个不同评分版本。资料库按球员归组；编辑任一版本的姓名、国籍、位置或球队，会同步到该球员的其他版本，评分只影响当前版本。普通模式可以把多个版本放进候选池，比赛模式也可以把多个版本放进位置候选；计算时同一球员在整份首发与替补名单中最多出现一次，比赛模式的所有位置选择也不会重复选择同一球员。
